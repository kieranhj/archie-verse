TrackMo Inspo
~~~
See Leonard's LDOS: https://github.com/arnaud-carre/ldos
Simple framework for loading executables and running them in order.
Takes care of loading the next file, decompressing it and then running.
Everything is blocking so up to the running exe to do this in the background.
How to run background tasks on Archie / RISCOS? (done, see above)

Will need more of a framework that LDOS, as can't just pass off the entire interrupt loop to each subsequent exe.

Something like:
    - Set up Error handler.
    - Allocate initial RISCOS buffers.
    - Set up initial video MODE.
    - Set up music.
    - Set up IRQ handler.
    - Don't set up sequence / script - this is FX specific.
    - Let each FX do its own screen buffer management.
    - Background loop just runs tasks in a queue?
    - Currently running foreground FX triggers load of next FX which adds a task:
        - cf. LDOS_PRELOAD_NEXT_FX
        - Load executable to safe address.
        - Initialise BSS.
        - Call init fn for new FX.
    - Currently running foreground FX decides when to hand off to next FX.
        - Just return from running exe.
        - Replace the vsync callback.
        - Will get called regardless - up to FX to determine frame swaps, palette swaps etc.

LDOS just runs in the main loop and blocks each fn.
Next FX is triggered when previous FX exits.
It doesn't attempt to impose a task system etc.
Although does handle memory management.
Relocates the exe to low memory just before execution to avoid fragmentation.
Parses the HUNK header to do this then clears BSS.

Which is kinda the point, particularly as ARM requires quite a lot of codegen/sprite shifting.

Spindle: C64 trackmo system by LFT.
~~~
Also specifies a list of files to be packed and sequenced on disk.
Call a memory resident loader (at $200) to load the next file.
Can also specify the RAM address, offset and file size.


Also has an effect linking system that's more 'hands on':
Specify fns for your effect with a fixed header plus optional flags that define memory areas used.

prepare - bulk of init, gen speedcode and tables, do not write to VIC registers (in parallel to running FX)
setup - initialise VIC regs just before the effect starts
interrupt - called on IRQ
main - intended for FX that don't run at 50Hz (newskool FX) (main thread, blocks loader)
fadeout - runs until Carry set (carry on)
cleanup - tear down in controlled fashion (interrupts enabled)

Sequence controls when and how next FX is triggered, default is 'press space'

Start with a demo sequence that has each effect and press space to continue.
Then look to overlap FX and see where Spindle inserts blanks for loading.
Then optimise to be seamless.

SMFX system just has three standard callbacks:
- vsync
- main loop
- MFP interrupt (for overscan)
The script is just a series of 3x fn labels, one for each callback, plus a frame counter.
Once the frame counter reaches zero it moves on to the next 3x callbacks in the list.
